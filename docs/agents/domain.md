# Domain documentation

I use a single domain context for this repository.

Before exploring, read the root `GLOSSARY.md` and relevant decisions in
`docs/adr/` when they exist. Continue without creating placeholders when
they are absent.

Use glossary terms consistently in specifications, architectural proposals,
and tests. Use domain-modeling when a resolved concept needs recording.
Create glossary entries and ADRs only when there is substantive content.

Continue reading `docs/system-context.md` and relevant component guides as
required by the agent guide. Existing documented decisions remain applicable.

Identify conflicts with recorded decisions and explain why a proposal
would justify revisiting them.
